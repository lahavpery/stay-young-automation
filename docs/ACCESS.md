# Secure official account access

Only account-owner login/authorization is requested. Never copy tokens, passwords or code into chat. Credentials belong in official connections and encrypted runner settings. The system has no existing secure social-account connector in this environment; OAuth apps and owner authorizations are still prerequisites, not completed integrations.

| Service | Official owner authorization | Secure runtime bindings |
|---|---|---|
| Facebook | Page plus eligible Meta app and Pages publishing permissions | FACEBOOK_PAGE_ID, FACEBOOK_PAGE_TOKEN, META_GRAPH_VERSION |
| Pinterest | Eligible API application, authorized account and writable board | PINTEREST_BOARD_ID, PINTEREST_TOKEN |
| Threads | Threads API app, account and publishing permissions | THREADS_ACCOUNT_ID, THREADS_TOKEN, THREADS_GRAPH_VERSION |
| Bluesky | Account and revocable official app-password connection | BLUESKY_HANDLE, BLUESKY_APP_PASSWORD |
| Mastodon (optional) | Official mastodon.social OAuth token with media/status permissions | MASTODON_BASE_URL, MASTODON_TOKEN |
| Instagram (optional) | Eligible professional account and Meta publishing permissions | INSTAGRAM_ACCOUNT_ID, INSTAGRAM_TOKEN, META_GRAPH_VERSION |
| GitHub | Repository write/workflow rights; public standard runner and public original-image hosting | GITHUB_TOKEN is generated by Actions; no owner token requested |

One owner approval is required before first social publication and recurring automation. Neither live flag is set. Free API access is subject to eligibility, current provider rules and quota; this code does not buy a plan or run paid fallback services.

The running environment denies GitHub API access. An environment configuration draft includes only official provider domains and api.github.com; the user must save/publish it through the environment UI before that policy changes. No course-site domain is included or needed. Do not connect to WordPress, WooCommerce, hosting, course content or payment systems.
